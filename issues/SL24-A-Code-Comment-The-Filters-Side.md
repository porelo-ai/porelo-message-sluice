# SL24 — A code comment, the filter's side

**Status:** Analyzed; blocked by porelo [B166](https://github.com/porelo-ai/porelo/blob/main/issues/base/README.md#b166), [B291](https://github.com/porelo-ai/porelo/blob/main/issues/base/README.md#b291), the one SARIF profile for every review, and [B292](https://github.com/porelo-ai/porelo/blob/main/issues/base/README.md#b292), the hardened SARIF reader on `java-sarif`. It does not wait for [SL23](README.md#sl23)'s narrowed schema: it works on today's envelope.
**Size:** L - direction-specific envelope rules for the closed SARIF 2.1.0 profile, pre-binding parser budgets, and a second set of detector thresholds measured on a code corpus.

**What must be true.** A review message (`comment`) carrying SARIF 2.1.0 ([PJ72](https://github.com/porelo-ai/porelo-project/blob/main/issues/README.md#pj72)) passes the filter only when it conforms to Porelo's closed, direction-specific SARIF profile within strict parser budgets: anchors are validated by shape as repository-relative paths and bounded line ranges, comment bodies are restricted to the safe Markdown subset and scanned as prose, and suggested replacements are confined to the anchored region and scanned by the encoded-payload, credential and personal-data detectors tuned on a code corpus. Any unpermitted SARIF field, unknown property-bag key or sender-claimed authority ([PJ73](https://github.com/porelo-ai/porelo-project/blob/main/issues/README.md#pj73)) is refused by a named rule in both directions.

## Why

Porelo exchanges every review comment, agent finding and forge review as SARIF 2.1.0 in one profile ([PJ72](https://github.com/porelo-ai/porelo-project/blob/main/issues/README.md#pj72)). A comment is a message, so it passes the controls every message passes ([`doc/filter.md`](../doc/filter.md#the-envelope)), and brings three problems today's rules do not cover:

- **The full SARIF 2.1.0 schema is far wider than a review comment.** Unchecked `properties` bags, external references, embedded `artifacts`, `snippet` and `contextRegion` blocks, `invocations`, `codeFlows`, `graphs`, `stacks`, HTTP evidence and multi-file `fixes` are covert payload, exfiltration or parser-exhaustion channels, and fields such as `tool.driver`, `suppressions` or `baselineState` can claim identity or a clean review ([PJ73](https://github.com/porelo-ai/porelo-project/blob/main/issues/README.md#pj73)).
- **The anchor names commits by their full hex ids.** A 40- or 64-digit lower-case hex string in `versionControlProvenance` or `porelo/baseRevisionId` is refused by `EncodingSignatureDetector` (`ENCODING/HEX`) when judged as prose, yet let through unchecked it would be a free-form channel.
- **A suggested replacement is code, not English prose.** The statistical detectors are calibrated on English prose (`EncodedPayloadRatesTest`); code has different symbol, letter and token distributions and would be refused for being code, while leaving `fixes` uninspected would open an 8 KiB channel for encoded payloads or secrets.

**Detectors are supplemental to containment, never the only control.** Persuasive instructions to an agent or a secret expressed in ordinary words can be valid prose and valid code ([PJ73](https://github.com/porelo-ai/porelo-project/blob/main/issues/README.md#pj73), [`doc/decisions.md`](../doc/decisions.md#no-language-model-inside-the-filter)). The filter enforces the closed shape and catches encoded payloads, credentials ([SL07](README.md#sl07)) and personal data ([SL32](README.md#sl32)); delivering review comments as untrusted data, restricting task permissions, and requiring human release and gate approval remain the host's containment controls.

## The shape

- **Closed SARIF 2.1.0 structure and parser budgets:** on today's envelope, a message whose `metadata.kind` is `comment` ([B166](https://github.com/porelo-ai/porelo/blob/main/issues/base/README.md#b166)) may carry exactly one `data` part, and every other message is still refused one (`ENVELOPE/DATA_PART_NOT_ALLOWED`); a `comment` without that part, with a second one, or with a `data` part on any other kind is refused by a rule of its own. The rest of the envelope stays as it is until [SL23](README.md#sl23) narrows it. The part is a single SARIF 2.1.0 document (`<= 1 MiB` UTF-8, `<= 32 KiB` per result) with root `version == "2.1.0"`, root `properties["porelo/profileVersion"] == "1"`, and a single `runs[0]` holding at most `100` `results[]`. Before any object binding, the JSON reader enforces `StreamReadConstraints` (`maxNestingDepth = 24`, `maxTokenCount = 100_000`, `maxStringLength = 16_384`, `maxNameLength = 128`, `maxNumberLength = 20`), strict UTF-8 without BOM or NUL, duplicate-key refusal, trailing-token refusal, unknown-property refusal, no scalar or single-element array coercions, and no polymorphic typing.
- **Anchors checked by grammar and excluded from prose detectors:**
  - `runs[0].versionControlProvenance[0]` carries only `repositoryUri` (matching the peer/repository name grammar) and `revisionId` (40 or 64 lower-case hex digits), and optional `runs[0].properties["porelo/baseRevisionId"]` follows the same 40- or 64-digit lower-case hex grammar; neither commit id is passed to the prose detectors.
  - `runs[0].results[].locations` has zero entries for a general comment or one `locations[0].physicalLocation` with `artifactLocation.uri` only: a non-empty repository-relative path of at most `1,024` decoded UTF-8 bytes (`<= 3,072` serialized ASCII bytes) using `/` separators and canonical percent-encoding (decoded once and re-encoded identically), with no scheme, authority, user info, query, fragment, leading `/`, `\`, drive prefix, empty segment, `.` or `..` segment, decoded `%`, NUL or control/format character. `uriBaseId` and `runs[].originalUriBaseIds` are refused.
  - `runs[0].results[].locations[0].physicalLocation.region`, when present, has `startLine >= 1`, `endLine >= startLine`, inclusive line span `endLine - startLine + 1 <= 100`, and optional `startColumn`, `endColumn` (`>= 1`) with `runs[0].columnKind == "unicodeCodePoints"`; `charOffset`, `charLength`, `byteOffset` and `byteLength` are refused. `relatedLocations` holds at most `4` locations under the same URI and region rules. Whether the commit, blob and lines exist is the host's check ([B166](https://github.com/porelo-ai/porelo/blob/main/issues/base/README.md#b166)).
- **Prose at `runs[0].results[].message`:** `message.text` is required and non-empty (`<= 8 KiB` UTF-8), and optional `message.markdown` (`<= 8 KiB` UTF-8) must represent the same text within the safe Markdown AST subset (paragraphs, simple lists, emphasis, inline code and fenced code, at most `4` structural nesting levels; raw HTML, SVG, MathML, scripts, styles, forms, images, `data:` URLs, external or bare URLs, custom or IDE protocols, local-file links and authoritative checkboxes are refused). `message.id`, `message.arguments` and message string dictionaries are refused. `message.text` and `message.markdown` go to every prose detector, including [SL07](README.md#sl07) and [SL32](README.md#sl32).
- **The single fix at `runs[0].results[].fixes`:** optional, at most one `fixes[0].artifactChanges[0].replacements[0]`, permitted only on a line-anchored comment with `properties["porelo/diffSide"] == "new"`, where `artifactChanges[0].artifactLocation.uri` equals the primary `artifactLocation.uri` and `deletedRegion` equals the primary `region`. `insertedContent` carries only `text` (at most the anchored line count plus `10` lines, at most `400` Unicode scalar values per line, and at most `8 KiB` UTF-8 in all); `fixes[].description` and `insertedContent.binary` or `rendered` are refused. `insertedContent.text` goes only to `LongTokenDetector`, `EncodingSignatureDetector` and `EntropyDetector` using `detector.<name>.code.*` thresholds calibrated on the code corpus, plus `CredentialDetector` ([SL07](README.md#sl07)) and `PersonalDataDetector` ([SL32](README.md#sl32)); `TokenShapeDetector` and `DistributionDetector` do not see it.
- **Direction-specific `*.properties` allow-list:** every property bag is flat scalars only (`<= 4 KiB` per bag; no nested objects, arrays, `tags` or extension maps) and admits only the profile's enumerated keys:
  - root `properties`: only `"porelo/profileVersion": "1"`;
  - `runs[0].properties`: `"porelo/projectId"`, `"porelo/repositoryId"`, `"porelo/baseRevisionId"`, `"porelo/reviewRound"`, `"porelo/completeness"` (`complete`, `partial`, `failed`, `unknown`), and optional `"porelo/reviewVerdict"` (`commented`, `approved`, `changesRequested`, `dismissed`);
  - `runs[0].results[].properties`: `"porelo/anchorKind"` (`line`, `file`, `general`), `"porelo/diffSide"` (`old`, `new`), UUID `"porelo/threadId"` and optional `"porelo/replyTo"`, `"porelo/threadState"` (`open`, `resolved`), `"porelo/sourceKind"` (`person`, `task`, `forge`, `scanner`), `"porelo/authorId"`, optional `"porelo/authorDisplayName"` (`<= 128` Unicode scalar values, no controls), `"porelo/taskId"`, `"porelo/taskRole"` (`developer`, `reviewer`), `"porelo/forgeInstanceId"`, `"porelo/nativeRepositoryId"`, `"porelo/pullRequestId"`, `"porelo/nativeCommentId"`, `"porelo/nativeThreadId"`, `"porelo/nativeReviewId"`, optional `"porelo/nativeState"`, and boolean `"porelo/outdated"`, `"porelo/draft"`, `"porelo/deleted"`.
- **Refused SARIF fields:** any unlisted SARIF field is refused, including `$schema`, `inlineExternalProperties`, `externalPropertyFileReferences`, `artifacts`, `snippet`, `contextRegion`, `attachments`, `graphs`, `graphTraversals`, `codeFlows`, `threadFlowLocations`, `stacks`, `addresses`, `webRequest`, `webResponse`, `webRequests`, `webResponses`, `taxonomies`, `policies`, `translations`, `tool.extensions`, `specialLocations`, `redactionTokens`, rule descriptors (`tool.driver.rules`, `globalMessageStrings`), `invocations` command/environment/stdio/notification fields, logical locations, location relationships, and any `*.properties` on nested objects.
- **Refused sender-claimed authority ([PJ73](https://github.com/porelo-ai/porelo-project/blob/main/issues/README.md#pj73)):** an outbound task submission is refused if it sets daemon- or adapter-owned fields: `porelo/sourceKind`, `porelo/authorId`, `porelo/authorDisplayName`, `porelo/taskId`, `porelo/taskRole`, `porelo/forgeInstanceId`, `porelo/native*`, `porelo/threadState`, `porelo/reviewVerdict`, `porelo/completeness`, `runs[].conversion`, `runs[].invocations`, `runs[].automationDetails`, `runs[].baselineGuid`, `results[].guid`, `results[].correlationGuid`, `results[].fingerprints`, `results[].suppressions`, `results[].baselineState`, `results[].hostedViewerUri` or `results[].workItemUris`.
- **Unicode bidi and zero-width controls refused:** Unicode format characters (bidirectional controls, zero-width spaces and joiners, tag characters, soft hyphen) and variation selectors are refused as `BLOCKING` across paths, identifiers, display names, comment prose and replacement code.
- **Same rules both ways, without rewriting:** inbound SARIF from a forge or scanner (after adapter normalization and daemon stamping) and outbound SARIF from a task pass the same structural, URI, Markdown, Unicode and detector checks, with direction-specific ownership checks on daemon- and adapter-owned keys. The filter never re-serializes or modifies a message ([`doc/decisions.md`](../doc/decisions.md#the-filter-never-rewrites-a-message)); it files the exact checked bytes, and every refusal reports its own rule id.

## Plan

- **Dependencies (`pom.xml`, `filter/app/pom.xml`):** the filter depends on no Porelo artifact (`AGENTS.md`, *What this repository is*), so it does not use [B292](https://github.com/porelo-ai/porelo/blob/main/issues/base/README.md#b292)'s reader module but holds its own copy of the same hardening. `filter/app/pom.xml` today declares only `com.fasterxml.jackson.core:jackson-databind` (versioned through `org.fuin:bom` in root `pom.xml`); add `com.contrastsecurity:java-sarif` 2.0 (new dependency) with its transitive Jackson 2.11 dependencies excluded and overridden by a current patched Jackson 2.x in `pom.xml`.
- **Parser budgets (`a2a/A2aReader`, `a2a/CheckConfig`):** `io/FileOps.read` and `MessageSluice.process` already cap input at `config.check().maxFileSizeBytes()` (`1 MiB` in `CheckConfig.defaults()`), and `A2aReader.parse` already enforces `strictUtf8`, `STRICT_DUPLICATE_DETECTION` and `FAIL_ON_TRAILING_TOKENS`. Extend `A2aReader` (and any `java-sarif` mapper) with `StreamReadConstraints` (`maxNestingDepth = 24`, `maxTokenCount = 100_000`, `maxStringLength = 16_384`, `maxNameLength = 128`, `maxNumberLength = 20`), `FAIL_ON_UNKNOWN_PROPERTIES`, `FAIL_ON_READING_DUP_TREE_KEY`, `FAIL_ON_NUMBERS_FOR_ENUMS`, disabled scalar/array coercions, and no polymorphic typing.
- **SARIF envelope check (`a2a/EnvelopeCheck`, new `a2a/SarifCheck`):** `EnvelopeCheck` reads the message's `metadata.kind` itself (today `metadata` is free-form and checked only for depth and size); when it is `comment`, `Walk.part` delegates the one `data` part to `SarifCheck` (new) instead of reporting `ENVELOPE/DATA_PART_NOT_ALLOWED`, and the kind rules above are new rules of `EnvelopeCheck`. `SarifCheck` enforces the closed SARIF 2.1.0 profile, per-result `32 KiB` bound, direction-specific `*.properties` allow-lists and forbidden task-claimed authority keys, `versionControlProvenance` and `baseRevisionId` hex shapes (not added to `Walk.texts`), canonical `artifactLocation.uri` and inclusive `region` (`endLine - startLine + 1 <= 100`), the safe Markdown AST check on `message.text` and `message.markdown`, the single-fix bounds on `fixes[0]`, and blocking refusal of Unicode bidi/zero-width controls, registering each rule id in `EnvelopeCheck.RULE_IDS`.
- **Code judged as code (`detect/TextUnderCheck`, `detect/DetectorRunner`, `Settings`):** `TextUnderCheck` gains a kind enum (`PROSE`, `CODE`, new). `DetectorRunner.run` runs all detectors on `PROSE` and routes `CODE` (`insertedContent.text`) only to `LongTokenDetector`, `EncodingSignatureDetector` and `EntropyDetector` built from new `detector.longToken.code.*`, `detector.signature.code.*` and `detector.entropy.code.*` keys in `Settings.DEFAULTS`, plus `CredentialDetector` ([SL07](README.md#sl07)) and `PersonalDataDetector` ([SL32](README.md#sl32)), skipping `TokenShapeDetector` and `DistributionDetector`.
- **The code corpus and fixtures:** freeze real source lines from this repository in `filter/app/src/test/resources/code-corpus.txt` (new, beside `english-corpus.txt`), add a code rates test beside `detect/EncodedPayloadRatesTest`, add `accept-`, `envelope-` and `detector-` fixtures under `filter/app/src/test/resources/fixtures/` (`FixturesTest`), and document the rules in `doc/filter.md`.
- **Red first:** a valid SARIF 2.1.0 `comment` message with a 40-digit hex `revisionId` in `versionControlProvenance[0]` and a Java replacement in `fixes[0]` is refused today by `ENVELOPE/DATA_PART_NOT_ALLOWED` (and by `ENCODING/HEX` if the commit id reaches the detectors); it must pass, while the same comment carrying a 32-character base64 blob in `insertedContent.text` or `results[0].suppressions` from a task must be refused by its specific rule.

## Acceptance

- One adversarial fixture per refused condition - wrong `version` or `porelo/profileVersion`, exceeded document/result/nesting/token/string budget, duplicate JSON key, malformed `revisionId`, non-canonical `artifactLocation.uri` (`..`, leading `/`, scheme, `%`, `uriBaseId`), `region` over `100` inclusive lines or with character/byte offsets, `message.markdown` with HTML, an image or an external link, `message.id`/`arguments`, a `fix` on `old` side or with `deletedRegion != region` or exceeding line/character/byte bounds, an unknown or non-scalar `*.properties` entry, a refused SARIF field (`$schema`, `artifacts`, `snippet`, `invocations`, `codeFlows`, `graphs`, `externalPropertyFileReferences`), sender-claimed authority (`porelo/sourceKind`, `porelo/reviewVerdict`, `suppressions`, `baselineState`, `conversion`), Unicode bidi or zero-width characters, and a base64 payload or credential in `insertedContent.text` - each refused by its own rule, and each test seen to fail with that rule removed.
- A comment in the closed SARIF 2.1.0 profile passes inbound and outbound, with and without a `fixes[0]` suggestion, and the file written to `accepted/` has the exact bytes of `incoming/`.
- **A code corpus** (`code-corpus.txt`) frozen beside `english-corpus.txt`, on which the code detectors keep false positives below 1 % on this repository's source lines and misses below 1 % on 32, 48 and 64 characters of encoded payload per encoding, as `EncodedPayloadRatesTest` measures for prose.
